# Правила работы с проектом

Игровые данные и записи раздела «Что нового» редактируются в `content/`.
Файлы `site/data/` создаются через `python generate.py` и не добавляются в Git.
Общие правила участия и проверки описаны в [CONTRIBUTING.md](CONTRIBUTING.md).

## «Что нового» и согласование перед деплоем

- Перед каждым деплоем подготовь запись для раздела «Что нового»
  (`content/news.yaml`) об обновлениях базы и значимых изменениях функциональности.
  Пиши о результате для игроков, без внутренних технических подробностей.
- Сначала закончи реализацию, подготовь локальный просмотр и выполни проверки.
  Затем покажи пользователю полный финальный текст записи: дату, заголовок,
  все пункты и ссылки. Получи явное согласование текста для текущего деплоя.
- До согласования не выполняй push в `main`, слияние в `main`, ручной запуск
  workflow публикации или другое действие, которое запускает деплой.
  В этом проекте push в `main` автоматически публикует сайт через GitHub Pages.
- Одобрение прошлой публикации не распространяется на следующие деплои.
  Если пользователь уже согласовал точный текст текущего обновления,
  повторно согласовывать его не нужно. При изменении смысла записи или состава
  публикуемых изменений покажи обновлённый текст для нового согласования.
- Если изменений для читателей нет, предложи публикацию без новой записи
  и согласуй это с пользователем. Не придумывай новость ради технического деплоя.
- Не удаляй прежние записи. Новые записи добавляй в начало списка;
  используй дату публикации по часовому поясу Europe/Moscow.
