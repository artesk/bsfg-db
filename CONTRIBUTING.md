# Как помочь проекту

Спасибо за исправления базы BSFG. Для изменения игровых данных не нужно уметь
программировать или устанавливать Git.

## Самый простой способ: форма ошибки

Создайте новую задачу и выберите форму **Ошибка в игровых данных**. Укажите:

- профессию и раздел;
- название умения;
- ветку и уровень;
- текущее и правильное значение;
- ссылку, скриншот или другое подтверждение, если оно есть.

## Самостоятельное исправление через сайт GitHub

1. Откройте каталог content/professions.
2. Выберите YAML-файл профессии. Имя файла совпадает с адресом карточки:
   expert.yaml, knight.yaml и так далее.
3. Нажмите карандаш **Edit this file**.
4. Найдите название умения сочетанием Ctrl+F или Cmd+F.
5. Измените только нужное поле.
6. Нажмите **Propose changes** и оформите Pull Request.

GitHub автоматически проверит файл. Если структура нарушена, в Pull Request
появится точный путь к ошибке.

## Структура записи умения

Каждый уровень выглядит примерно так:

    - branch: base
      description: Увеличивает максимум переносимого веса.
      effects:
      - kind: value
        text: 'Переносимый вес: 160%'
      icon: /icon/s10537.jpg
      level: '4'
      name: Грузоподъемность
      selection_id: ''
      specifications:
      - 'Уровень изучения: 60'
      - 'Тип умения: Пассивный'
      - 'Класс умения: Физический'

Допустимые значения branch:

- base — основная ветка или обычное умение;
- one — первая особая ветка;
- two — вторая особая ветка;
- three — третья особая ветка.

Уровень всегда оставляйте строкой в кавычках: level: '7'. Не меняйте slug,
source.data_sha256 и source.original_url при обычном исправлении данных.

Если запись уже сверена с клиентом, ищите её по `skill_id` и `level` внутри
карточки с нужным `class_id`. Меняйте ID только по подтверждённому соответствию.

## Что можно исправлять

- название и описание профессии;
- название и описание умения;
- уровень изучения и другие характеристики;
- значения эффектов;
- путь к корректной архивной иконке;
- ошибки интерфейса, доступности и мобильной версии.

## Чего не следует добавлять

- непроверенные значения без пояснения источника;
- персональные данные, ключи доступа и пароли;
- HTML или JavaScript внутрь YAML;
- изображения, на распространение которых явно нет разрешения;
- сгенерированные файлы site/data.

## Проверка на компьютере

    python3 -m venv .venv
    .venv/bin/pip install -r requirements.txt
    .venv/bin/python generate.py --validate-only
    .venv/bin/python generate.py
    node --check site/assets/app.js

## Правила Pull Request

- Один Pull Request — одна связанная группа исправлений.
- В описании перечислите изменённые профессии и уровни.
- Не форматируйте целиком большой YAML-файл ради одной строки.
- Не редактируйте контрольные суммы и метаданные слепка без обновления источника.
- Все автоматические проверки должны завершиться успешно.

## Для сопровождающих: новый слепок

Импорт полного слепка заменяет пользовательский слой и поэтому выполняется в
отдельной ветке:

    python3 import_snapshot.py --snapshot /path/to/snapshot --force
    python3 generate.py --validate-only

После импорта нужно перенести актуальные исправления сообщества и внимательно
просмотреть разницу перед слиянием.
