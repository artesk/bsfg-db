# Открытая база профессий BSFG

Статический архив профессий Battles for Glory с поиском, уровнями и ветками
умений. Сайт не требует сервера приложений и может публиковаться на GitHub Pages.

Действующая копия: <https://45.95.235.235.nip.io/bsfg-db/>

## Как устроен проект

Проект намеренно разделён на независимые слои:

- **content/** — понятные YAML-файлы, которые редактируют участники;
- **site/** — HTML, CSS, JavaScript и изображения интерфейса;
- **site/data/** — автоматически созданные JSON-файлы для браузера, они не
  хранятся в Git;
- **generate.py** — проверяет YAML и собирает браузерные данные;
- **import_snapshot.py** — служебный импорт нового проверенного слепка;
- **import_wayback_icons.py** — необязательное восстановление иконок из Wayback.

Одна профессия соответствует одному файлу:

    content/professions/expert.yaml
    content/professions/knight.yaml
    content/professions/wizard.yaml

## Как предложить исправление без программирования

1. Откройте нужный файл в content/professions/.
2. Нажмите значок карандаша **Edit this file** на GitHub.
3. Найдите название умения через поиск браузера.
4. Исправьте описание, характеристику или эффект.
5. Нажмите **Propose changes** и создайте Pull Request.

Не редактируйте site/data: этот каталог создаётся заново при каждой сборке.
Если YAML редактировать неудобно, создайте задачу через форму **Ошибка в игровых
данных** — в ней достаточно указать профессию, умение, уровень и правильное
значение.

Подробная инструкция находится в [CONTRIBUTING.md](CONTRIBUTING.md).

## Локальная проверка

Понадобятся Python 3.11+ и Node.js для проверки синтаксиса интерфейса.

    python3 -m venv .venv
    .venv/bin/pip install -r requirements.txt
    .venv/bin/python generate.py
    node --check site/assets/app.js
    python3 -m http.server 8080 --directory site

После этого сайт доступен по адресу <http://127.0.0.1:8080/>.

Только проверить YAML, не создавая JSON:

    .venv/bin/python generate.py --validate-only

## Автоматизация GitHub

- validate.yml проверяет каждый Pull Request и собирает данные во временный
  каталог;
- pages.yml после изменения ветки main собирает сайт и публикует папку site/ на
  GitHub Pages;
- публикация не содержит Python, исходные YAML или служебные скрипты.

После создания репозитория владельцу достаточно открыть **Settings → Pages** и
выбрать источником **GitHub Actions**.

## Обновление исходного слепка

Импорт намеренно требует явный путь и флаг подтверждения, если YAML уже
существуют:

    python3 import_snapshot.py --snapshot /path/to/completed-snapshot --force
    python3 generate.py

Перед таким обновлением нужно сохранить пользовательские изменения: импорт
заменяет редактируемый слой данными нового слепка.

## Происхождение данных и изображений

Игровые значения происходят из проверенного слепка базы BSFG. Иконки отдельно
восстановлены из архивных копий старого домена через Wayback Machine. В каждом
YAML-файле сохранены исходный URL и контрольная сумма импортированной карточки.

Код проекта, игровые данные и изображения должны лицензироваться раздельно.
Игровые названия, данные и изображения не объявляются собственностью авторов
этого репозитория. Перед публичной публикацией владельцу репозитория необходимо
выбрать лицензию именно для программного кода.
