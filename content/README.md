# Редактируемые данные

Это единственный источник игровых данных для сайта.

- metadata.yaml описывает исходный слепок целиком;
- news.yaml содержит записи раздела «Что нового»: дату, заголовок, список изменений и ссылки на разделы сайта. Перед каждым деплоем текст записи согласовывается с владельцем проекта; порядок описан в ../CONTRIBUTING.md;
- collections.yaml содержит каталог коллекций: характеристики, предметы, отдельные варианты состава и дополнительные предметы для реликтовых коллекций. `effects.value` хранит знак эффекта, `unit: percent` означает проценты, `unit: flat` — единицы. `characteristic_id` ссылается на `characteristics.id`, а `item_id` — на `items.id`. Варианты состава являются альтернативами; их нельзя объединять в общий список необходимых предметов. Количество каждого предмета хранится в `count`;
- guides/*.yaml содержит текстовые гайды: вступление, краткие сведения, разделы с абзацами, списками и таблицами, а также источники. Необязательное поле `image` содержит локальный `src` из `site/assets/guides/` (без префикса `site/`), описание `alt` и исходные размеры `width`/`height`. Гайд «Форпост» хранится в guides/forpost.yaml; его итоговый текст согласовывается с владельцем проекта до публикации. Гайд «Амулет Сновидений» хранится в guides/dream-amulet.yaml; гайд «Остров осужденных» — в guides/condemned-island.yaml;
- professions/*.yaml содержит карточки отдельных профессий;
- specifications/*.yaml содержит таблицы характеристик, в том числе уровни знамён, реликвий, свойств экипировки и наград за военную службу;
- specifications/guild-skills.yaml содержит описания и требования к строениям из клиента, а также числовые бонусы умений гильдии из слепка базы;
- specifications/sibyl-cards.yaml содержит описания карт из клиента и общую таблицу требований и затрат `upgrade_costs`, собранную по данным из игры и сведениям сообщества. В ней `level` — получаемый уровень карты, `character_level` — минимальный уровень персонажа. Количества указаны за одно улучшение: `closed_cards` — закрытые карты, `gold` — золото, `knack` — сноровка, `book_fragments` — обрывки утерянных книг. `0` означает, что ресурс не требуется, `null` — количество неизвестно. Новые наблюдения добавляйте в эту таблицу с обновлением её `source` и `note`, не меняя `client_release` описаний;
- items/equipment.yaml содержит экипировку, рецепты и комплекты. Части комплекта связаны с предметами по клиентскому ID;
- site/data создаётся командой python3 generate.py и вручную не редактируется.

В `specifications/sibyl-cards.yaml` таблицы характеристик хранятся в поле `parameters`:
`columns` задаёт названия характеристик, `levels` содержит уровень и массив
`values` в том же порядке. Значения хранятся строками с исходными знаками и
единицами, `null` означает неизвестное значение. Все эти таблицы имеют статус
`verification: required` и видимую пометку «Данные требуют верификации».
Они не относятся к клиентскому источнику общих описаний. Пустые ячейки не
заполняются расчётом; существующие `levels.effect` и `upgrade_costs` сохраняются.

## Быстро найти нужную запись

1. Откройте файл профессии.
2. Найдите строку name: с названием умения.
3. Рядом проверьте branch и level.
4. Измените description, specifications или effects.

В некоторых профессиях существуют разные умения с одинаковым названием.
Обязательно сверяйте icon, описание и соседние эффекты.

## Сверка с клиентом игры

Коллекции сверены с `ExCollectionData-ru.dat`, `ExCollectionEffect-ru.dat`,
`ExCollectionEffectCategory-ru.dat` и `ItemName-ru.dat`; хеши файлов находятся в
`collections.yaml → source`. Единицы и знаки эффектов проверены по
`BsfgMainCollectionWnd.CalculateCollectionStats` из `Interface.u`. Исходные
названия характеристик с исправленными опечатками сохранены в `source_name`.
Показаны базовые бонусы. `purchase_gold` — цена покупки обычной коллекции вместо
сбора, `relic_purchase_gold` — цена реликтовой коллекции; обе в золоте. Поля
сопоставлены с `m_Price` и `m_RelictPrice` через загрузчик `smackw32.dll`, структуру
`UIExCollectionData` и подсказки покупки в `Interface.u`/`SysString-ru.dat`.
Нулевая реликтовая цена не импортируется и не означает бесплатную покупку.
Реликтовые цены показываются только для разрешённых клиентом реликтовых вариантов
(`m_bCanBeRelict`). У «Глубоких познаний алхимии» поле цены заполнено, но вариант
отключён, поэтому эта реликтовая цена исключена.
Ограничения уровня пока не импортированы.
Варианты 0–5 названы по расовым меткам предметов. У «Гурмана» вариант 7 назван
«Рыба, эль и фрукт» по составу: соответствие кода расе ещё не подтверждено.
Нулевой предмет с нулевым количеством у «Новогоднего переполоха» исключён как
пустой слот. Раса выбирается один раз для всего каталога; поиск по предметам
учитывает выбранный расовый и общий состав. Дополнительный вариант «Гурмана»
сохранён отдельно. Иконка обязательна для каждого предмета. Недостающие изображения
сопоставлены через `object_id`/`icon1` и извлечены из пакетов клиента;
`source.icons` содержит хеши источников. Существующие PNG переиспользованы при
совпадении пикселей. У «Флага союза» ссылка `bsfg.s297` не указывает группу:
для изображения выбран флаг `Bsfg.New.s297`; в пакете также есть вариант
`Bsfg.SkillNew.s297` с другим фоном.

- `profession.class_id` — ID профессии из `ExClassInfo-ru.dat`.
- `skill_id` в записи умения — ID из `SkillName-ru.dat` и `Skillgrp.dat`.
  Для сверки используйте пару `skill_id` и `level` с клиентским подуровнем 0.
  У веток одного умения могут быть разные ID. Записи без уверенного соответствия
  остаются без `skill_id`.
- `branch_group_id` у новых карточек содержит `skill_id` первой ветки. Это
  позволяет показывать три варианта вместе, даже если у них разные названия.
- `source.client_release` указывает выпуск клиента, с которым сверяли карточку.
  `source.data_sha256` и `source.original_url` относятся к сентябрьскому слепку.
  У карточек, собранных из клиента, этих двух полей нет.
- `effects_from_archive: true` помечает эффекты, которые остались в карточке для
  справки после изменения клиентского описания. Сайт показывает их отдельно.
- Когда клиент подтверждает только часть таблицы, в `effects` записываются
  подтверждённые строки, а в `archived_effects` остаются данные слепка.

Русские описания умений берутся из `SkillName-ru.dat`. Иконки сверяются по
`Skillgrp.dat` с использованием пула имён того же релиза. Уровни изучения,
минимальные откаты и подробные таблицы эффектов из сентябрьского слепка
требуют отдельного подтверждения. У новых карточек такие поля оставлены пустыми.

16 ноября 2026 года восстановлены уровни 2–5 у 148 специальных умений,
для которых в архиве был только первый уровень с требованием изучения 90.
Дополнение сверено с клиентом `2026.11.11.220300`: принадлежность профессии —
по `ExClassInfo-ru.dat`, цепочка уровней и отдельные описания — по
`SkillName-ru.dat` с подуровнем 0, иконки — по `Skillgrp.dat`.
Названия и описания первых уровней совпали с клиентом. Исходные записи
первого уровня сохранены; новые уровни добавлены сразу после них.
Тип и класс умения сохранены из первого уровня при неизменных клиентских
`operate_type` и `is_magic`. Требования изучения, откаты, дистанции и таблицы
эффектов первого уровня на новые уровни не переносятся. Числовые бонусы новых
уровней указаны в клиентских описаниях. `source.client_release` всей карточки
остаётся датой её прежней полной сверки; это дополнение не означает повторную
проверку остальных умений профессии.

## Важные правила YAML

- сохраняйте отступы пробелами;
- уровни оставляйте в кавычках, например level: '7';
- текст со знаком двоеточия лучше оставлять в кавычках;
- не используйте табуляцию;
- не меняйте slug: он должен совпадать с именем файла;
- не меняйте source без обновления исходного слепка.

Проверка структуры:

    python3 generate.py --validate-only

Полная инструкция для участников находится в ../CONTRIBUTING.md.
